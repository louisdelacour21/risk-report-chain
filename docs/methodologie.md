# Methodology

All figures in the demo come from **synthetic** data generated by `synth/generate.py`. Nothing here describes a real bank's process.

## Scope
Three desks (EQUITY, RATES, FX), about 52 positions: equities, index futures, European options, annual-coupon bonds, FX cash. Calendar: TARGET2. Day count ACT/365. `fx[ccy]` is units of currency per EUR.

## Inputs
Eight CSV extractions per as-of date, in `data/inbox/<date>/`: `positions_fo`, `positions_bo`, `statics`, `prices`, `fx`, `limits`, `pnl_fo`, `factor_history`. Each has a strict schema (pandera) and its own CSV dialect (the back office uses `;` and a decimal comma).

## Valuation and hypothetical P&L
Full revaluation: equities `q*P`, futures `q*P*multiplier`, Black-Scholes European options (vectorised, intrinsic at expiry), bonds by discounting at the pillar yield (DV01 = V(y) - V(y+1bp)), FX cash `q/fx`. Hypothetical P&L = value at the as-of state minus value at T-1 with positions held fixed.

## P&L explain
Greeks are taken at the T-1 state: `delta*dS + 1/2*gamma*dS^2 + vega*dIV + theta*dt - DV01*dy + FX effect`. Cross terms stay in the unexplained part. Per desk: `unexplained = P&L_FO - explained`; `model_residual = hypothetical - explained`. Alert threshold: `max(5% * |P&L|, 10,000 EUR)`. Tests: linear positions leave a residual of exactly 0; for a lone option the residual scales like the cube of the move.

## VaR and ES
500 historical scenarios drawn from `factor_history`, each applied to the current book with full revaluation at the next business day. VaR 99% is the 5th worst scenario; ES 97.5% is the mean of the 13 worst (`ceil(12.5)`). Desk ES contributions are the desk's mean P&L over the portfolio's 13 worst scenarios, so they add up to the total. The engine is `riskhub-engine` 0.1.0 (`market.historical`).

## Backtest
The book is held fixed and each historical change is applied once to today's levels. The VaR of day t uses the 500 changes before t; an exception is a day whose P&L is below -VaR. With 750 days of history, 249 days are tested. Kupiec's proportion-of-failures likelihood ratio is compared with chi2(1); the Basel traffic light uses 4 / 9 exceptions as the green / yellow limits. The result is reported, never blocking.

## Limits
Usage = value / limit. OK below 85%, ALERT from 85% to 100%, BREACH above 100%. A breach is a **result**, reported in the workbook and the commentary; it does not change the run status.

## Controls (C01-C14)
Blocking (B) controls give `NOT_VALIDATED`; alert (A) controls give `WITH_RESERVATIONS`.

| ID | Control | Sev. |
|----|---------|------|
| C01 | Files present, folder date = as-of, series reach the as-of date | B |
| C02 | Schema, types, bounds | B |
| C03 | Duplicate (book, instrument) | B |
| C04 | Position without static data | B |
| C05 | Missing price (T-1 used); more than one day missing is blocking | A/B |
| C06 | Stale price (unchanged for 3 days or more) | A |
| C07 | Jump larger than 6 EWMA volatilities | A |
| C08 | FO / BO reconciliation (exact quantity, nominal within 1,000 EUR) | A |
| C09 | Missing FX rate | B |
| C10 | Scenario history complete (500 scenarios, no gaps) | B |
| C11 | Option inputs plausible (vol in [1%, 300%], T > 0) | A |
| C12 | FO P&L against explained P&L, per desk | A |
| C13 | Hypothetical P&L against explained P&L (model adequacy) | A |
| C14 | The workbook, re-read with openpyxl, matches the computed VaR, ES and P&L | B |

Exit codes: 0 validated, 1 with reservations, 2 not validated, 3 crash. A not-validated run still produces a workbook, with a red banner.

## Traceability
Each run is archived in `runs/<date>[_v2]/`: copy of the inputs, `report.xlsx`, `results.json`, `manifest.json` (SHA-256 of every input and of the config, library versions), `journal.jsonl` and a `.eml` notification. `riskreport rerun <dir>` replays the run from the archived inputs and compares every number at relative 1e-9.

## Commentary
Template sentences filled from the numbers. No language model is involved.

## Limits of this work
- The "auto-review" (C01-C14) is the chain checking itself. It is **not** an independent validation.
- Synthetic data only: it proves the mechanics, not that the controls would fit a real book.
- The benchmark (see README) injects the defects the controls were designed for, so detection rates are an upper bound on what unseen defects would give.
- No intraday, no stressed VaR, no multi-day horizon, no netting or collateral.
